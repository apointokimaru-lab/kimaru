# 30. ピンポイント日程調整（/p/ リンク）

対象: 発行者（ホスト）／ゲスト　状態: 実装済み（#303）

## これは何か

通常の予約ページ（`/b/<slug>`）は「受付時間の空き枠すべて」をゲストに見せる。
ピンポイント日程調整は、ホストが**あらかじめ選んだ数枠だけ**を提示する専用リンク。

「この3つのどれかでいかがですか」と個別に打診したいときに使う。ゲストはカレンダーを
操作せず、提示された候補から1つ選ぶだけで済む。

## 決定事項（#303）

| 項目 | 決定 | 理由 |
|---|---|---|
| リンクの使い切り | **何人でも使える**（候補が埋まるまで有効） | 同じ候補を複数人に打診する使い方を想定 |
| 候補枠の確保 | **リンクごとに選べる**（`hold_slots`） | 確実に押さえたい打診と、先着でよい打診の両方がある |
| 候補の選択元 | キマルが算出した空き枠のみ | 受付時間・前後バッファ・Googleカレンダーとの整合を崩さない |
| リンク管理画面 | ~~今回は作らない~~ → **作る**（2026-08-18・#327） | 発行直後にURLをコピーできれば足りると判断したが、期限（#326）と押さえの状態を後から確認・解除する手段が無かった |
| 有効期限 | **3日/1週間から選ぶ**（2026-08-18・#326） | 当初は「候補が過ぎれば自然に無効」で足りると判断したが、打診が流れたリンクと押さえがいつまでも残るため |
| 配信範囲 | **当面プレミアム限定**（2026-08-13） | まず限定配信して使われ方を見る。恒久的な決定ではない |

## プラン

**リンクの発行はプレミアムのみ。** 無料・Pro には予約ページ一覧の「ピンポイントリンク」ボタン自体を出さない
（`app.js` `renderBookingPages`）。サーバ側も `pinpoint-create.js` が `requirePremiumOwner` で 403 にする。

**ゲスト側（`/p/<token>`）はプランで絞らない。** 絞ると、発行者がプランを下げただけで**すでに相手に
送ったリンクが切れる**。約束を反故にすることになるので、発行済みリンクは開けるままにする
（他のプラン変更と同じ grandfathering の方針）。

## URL

`/p/<token>` → `booking.html`（`netlify.toml` の rewrite。`/b/*` と同じページを使い、
`booking-week.js` が token の有無でピンポイント表示に切り替える）。
token は推測されないランダム文字列。slug と違い、URLを知っている人だけが開ける。

## データ

`pinpoint_links`（`supabase-schema.sql`）

| 列 | 意味 |
|---|---|
| `token` | URLの `/p/<token>`。一意 |
| `booking_page_id` | どの予約ページの設定（所要・バッファ・質問・開催方法）を使うか |
| `slots` | 発行時に選んだ候補枠のスナップショット `[{start, end}, ...]`（ISO8601・UTC） |
| `hold_slots` | true なら、この候補枠を通常の予約ページからも埋められないよう押さえる |
| `hold_title` | 押さえ予定の予定項目名（`hold_slots` が true なら必須） |
| `hold_events` | 作成した押さえ予定 `[{start, end, event_id}, ...]`。時間帯も持つのは自分の押さえを busy から引くため |
| `expires_at` | リンクの有効期限（発行時に3日/1週間から選ぶ）。null は無期限 |
| `is_active` | 発行者が止めたときに false |

候補は**スナップショットで持つ**。受付時間や所要時間を後から変えても、打診済みの候補は
変わらないほうが約束として正しいため。

## 枠の確保（`hold_slots`）

押さえは**2段構え**になっている。

1. **キマル内部** — `hold_slots = true` のリンクの候補枠を、空き枠計算の busy に加える
   （`_lib/pinpoint.js` `heldBusyFor` → `_lib/availability-core.js`）。通常の予約ページから選べなくなる
2. **Googleカレンダー** — 発行時に、候補それぞれをホストのカレンダーに実際の予定として作る
   （`createHoldEvents`・#325）

1 だけだった頃は、ホストが自分のカレンダーを見てもその時間が空いて見え、**Google側から直接
埋められた**。2 はその穴をふさぐもの。逆に 2 だけにはできない（Google未連携のアカウントが
あるため）ので、両方要る。

押さえ予定は `transparency: "opaque"` で作る。`"transparent"` にすると freeBusy に返らず、
押さえた枠の上に次の予約が入る（#300 と同じ罠）。`_lib/google.js` の `createBufferEvent` を
バッファ予定と共用している。

### 予定項目名（必須）

「押さえる」を選んだときだけ予定項目名の欄を出し、**必須**にする。空のまま発行できると
カレンダーに予定が作られず、「押さえたのに何も起きない」状態になるため（サーバも400で止める）。
前後バッファの予定名（#321）と同じ考え方。

### Googleカレンダー連携が必須（#327 レビュー指摘）

**未連携では「押さえる」を選べない。** 選択肢を disabled にし、押せない理由と連携への導線を
選択肢のすぐ下に出す。サーバ側（`pinpoint-create.js`）も未連携＋押さえなら 400 で止める。

当初は未連携でも押さえられ、1（キマル内部）だけが効く作りだった。やめた理由は、
**必須にした予定名がどこにも現れない**ため。予定名を必須にした根拠は「空だと予定が作られず、
設定したのに何も起きない」（#325）だったのに、未連携はまさにその状態を、名前を入力させた
うえで許していた。「押さえる」の意味が連携の有無で2つに割れる点も、説明を増やしていた。

失うのは「未連携でもキマル経由の二重予約は防げた」点だが、キマルはそもそもカレンダー連携が
前提に近い（空き枠判定・予定自動作成・Meet発行に必要）ので、押さえだけ例外にしない。

### 自分自身の押さえだけを除外する

`/p/<token>` を開いたゲストには、そのリンクの候補がそのまま出る必要がある。ここは**2段とも
除外しないと壊れる**（#325）:

- `heldBusyFor` の `exceptId` で自分を外す … 1 に対応
- Googleの予定から自分の押さえを外す … 2 に対応

2 を省くと、自分で作った押さえ予定を Google が busy として返し、**ゲストの画面から候補が
1つも出なくなる**。

**除外は freeBusy ではなく events API で行う（#334）。** freeBusy は重なり合う予定をマージして
1本の区間で返し、イベントIDも返さない。当初は `hold_events` に時間帯を持たせて時間で引いて
いたが、押さえとバッファ予定が重なると次のように壊れた:

```
押さえ    13:00-14:00
バッファ  13:00-13:30
freeBusy  → 13:00-14:00（1本にマージ）
時間で引く → 丸ごと消える → バッファで埋まった13:00-13:30が「空き」に見える
```

#325 では「実予約と押さえが重なってもキマル経由の予約は `bookings` 由来の busy で守られる」と
していたが、**バッファ予定は Google カレンダーにしか無く `bookings` に無い**ので保護が効かない。
バッファは前後に必ず付く運用なので、稀どころか日常的に踏む。

そこで、除外するものがあるとき（＝ピンポイント）だけ `eventsBusy()` で予定を1件ずつ取り、
**イベントIDで押さえだけを外す**。freeBusy と意味を合わせるため `status:"cancelled"` と
`transparency:"transparent"` は busy に数えない。除外するものが無い通常の予約ページは
freeBusy のまま（軽いので据え置き）。

events API が失敗したときは freeBusy ＋ 時間での差し引き（`subtractHold`）に落とす。
精度は #334 以前に戻るが、取れないよりはよい。

## 有効期限（#326）

発行時に **3日 / 1週間** から選ぶ（既定は1週間）。

**期限は「リンクの有効期限」で、候補の日時とは独立している。** 期限3日のリンクに10日後の候補が
入っていてよい。期限が来ればリンクは切れ、候補が未来かどうかに関わらず予約できなくなる。
期限内に予約が入っていれば、正式な予約とGoogleカレンダーの予定が別途できあがっているので、
あとから押さえ予定を消しても成立済みの予約には影響しない。

`expires_at` が null は無期限。#326 より前に発行済みのリンクは null のまま据え置く
（遡って期限を付けない）。列が未適用の環境でも全リンクが無期限として動く。

### 期限が切れたら

- **キマル側の押さえはすぐ解ける** — `heldBusyFor` が期限切れのリンクを外すので、
  片付けジョブを待たずに枠が他の予約へ開放される
- **Googleの押さえ予定は定期ジョブが消す** — `pinpoint-expire.js` の `run()` を
  `pinpoint-expire-scheduled.js` が1時間ごとに呼ぶ（`netlify.toml`）。分単位の精度は要らない。
  ローカル確認は `/api/pinpoint-expire?dry_run=1`（認証は `REMINDER_CRON_SECRET`／`CRON_SECRET`）

消すのは**押さえ予定だけ**。そのリンク経由で成立した実際の予約とその予定には触らない
（別イベントとして作られ `hold_events` に入っていないので、そもそも辿れない）。

片付け済みの目印は **`hold_events` を空にすること**。空にしないと、削除済みの予定に対して
毎時 Google へ DELETE を投げ続ける（404は成功扱いなので無害だが無駄打ちになる）。
逆に削除が全部失敗したときは空にせず、次の実行でもう一度試す。

### ゲストに何を見せるか

期限切れは **404 にせず「有効期限が切れています」と出す**。受付停止（#321）を404にしたのは
「時間を置けば予約できる」と誤読させないためだが、期限切れは逆で、相手はこのリンクを実際に
受け取った正規の宛先。切れたと分からないと「主催者に連絡する」という次の行動に進めない。

存在しない・停止済みを同じ404にまとめる方針（トークン探索対策）自体は変えていない。
トークンは22桁の乱数なので、ここを区別しても総当たりの助けにはならない。

## リンク一覧と手動の無効化（#327）

### 置き場所

**`booking-settings.html` の中のビュー切り替え**にした（`#pinpoint-list-view`）。新規ページも
ナビ項目も増やしていない。理由:

- 「ピンポイントリンクを作成」が既に同じ作りのビュー切り替え（`#pinpoint-view`）なので揃う
- #321 でヘッダーとスマホ下部のナビを整理した直後なので、項目を増やしたくない
- リンクは予約ページの設定に紐づくもので、単体では意味が読めない

ただし**一覧の中身は予約ページ横断**。ホストが見たいのは「自分が送ったリンク」であって
「このページのリンク」ではないため。どの予約ページのものかは行の中に出す。

入口は予約ページ一覧の見出し横のボタン（`#pp-list-open`）。発行と同じくプレミアム限定なので、
`updateBookingPageControls` が描画時に出し入れする（`.premium-feature` は `display:block` に
なるため、横並びのボタン列には使えない）。

### 行に出すもの

対象の予約ページ／候補の件数と最初〜最後の日時／押さえの有無と予定名／期限／状態
（有効・期限切れ・無効）／URLコピー・無効にする。

**無効にできるのは「有効」のリンクだけ。** 期限切れ・無効化済みは押さえも既に解けているので、
ボタンを出しても何も起きない（押せるのに何も起きない状態を作らない）。

### 無効化は取り消せない

押さえていたGoogleカレンダーの予定を消してしまうので、`is_active` を戻しても同じ状態には
復元できない。**「一度無効にすると有効にはできません」とモーダルで宣言してから実行し、
戻す導線は作らない**（作ると宣言と食い違う）。サーバ側 `pinpoint-deactivate.js` にも
戻す経路は無い。

対象はURLで表示する。同じ予約ページから複数のリンクを発行できるので、ページ名だけでは
どのリンクを止めるのか特定できない。

押さえの解除は期限切れ（#326）と同じ `releaseHold()` を使う。予定の削除に失敗しても
無効化そのものは進める（リンクを止めたいのが主目的で、止まらないほうが困る）。

### 一覧からの削除（#336）

**使えなくなったリンク（無効・期限切れ）だけ物理削除できる。** 無効化しても行は残り続け、
打診を重ねるほど一覧が読みにくくなるため。

**有効なリンクは削除できない**（画面にボタンを出さず、サーバも400で拒否する）。行を消すだけで、
相手がまだ開けるリンクを黙って死なせないため。止めたいなら先に「無効にする」を通す
（あちらは押さえの解除と遮断を伴う）。

期限切れも削除対象にしているのは、**期限切れは無効化できない**から（「無効にする」は有効な
リンクにしか出さない）。無効だけを対象にすると、期限切れが一生消せない行として残る。

削除の前に `releaseHold()` を呼ぶ。期限切れ直後は片付けジョブ（#326）がまだ走っておらず
`hold_events` が残っていることがあり、そのまま行を消すと**二度と辿れないGoogle予定が残る**。

## 予約成立

ゲストの予約は既存の `book.js` を通す。`pinpoint_token` を受け取ったときだけ、
**選ばれた開始時刻がそのリンクの候補に含まれるか**をサーバ側で検証する。
候補外の時刻をPOSTされても成立させない。

リンクは何人でも使えるため、候補のうち既に埋まったものは
ゲスト側の一覧から除く（表示時に空き枠計算で突き合わせる）。

## 画面

- **ホスト**: 予約ページ一覧の「URLをコピー」の隣に「ピンポイントリンク」ボタン。押すと
  一覧・編集と同じ全幅の**候補選択画面**に切り替わる（`booking-settings.html` の `#pinpoint-view`／
  `app.js` の `openPinpointView`）。
  画面は**ゲストの予約画面と同じタイムグリッド**（`week-grid.js` を共用。前後送り・
  範囲ボタンから月カレンダー）で、**枠を押すと候補に入り、もう一度押すと外れる**。
  表示日数は画面幅で決まる（**スマホ5日 / PC1週間**）。PCで5日だと横に余白が余り、週の
  見通しが悪かったため。日数は `availability` の `days`（許可リストは5と7）で受ける。
  選んだ枠は白抜き→朱ベタ＋✓に反転し、下のトレイに時刻順のチップとして並ぶ（✕で取り消せる）。
  枠の押さえ方は他の設定と同じ**プルダウン**（押さえない＝先着順／押さえる＝他の予約を入れない）。
  発行するとURLが出るのでコピーして相手に送る。選択は日を送っても保持される。

  グリッドの描画は `public/week-grid.js`（`window.KimaruWeekGrid.render`）に切り出し、
  ゲストの `booking-week.js` と共用している。**選択の意味だけ**が違う（予約＝1つ選ぶ／
  候補選択＝複数トグル）ので、`isSelected` / `onPick` / `picker` で呼び出し側が決める。
- **ゲスト**: `/p/<token>` は **`booking.html` を再利用する**（`netlify.toml` の rewrite）。
  `booking-week.js` がパスからトークンを読み、週表・月カレンダーを隠して候補をラジオ一覧で出す
  （「2026年8月20日（木）14:00〜14:30」形式・`fmtSlotRange`）。
  選ぶと通常の予約と同じフォームが現れ、質問・確認・完了はそのまま既存フローを通る。
  予約時は `pinpoint_token` を載せ、サーバ側で候補内かを再検証する。

専用HTMLを作らず `booking.html` を再利用したのは、質問・確認・完了の画面とロジックを
二重に持つと、片方だけ直して食い違う事故が起きるため。差し替えるのは候補の出し方だけにした。
