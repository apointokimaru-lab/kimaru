- **本番は Netlify に一本化**（承認済み）。**Vercel 対応は廃止**＝`vercel.json` / `api/*` アダプタ / `lib/vercel-adapter.js` を削除。サーバー処理は `netlify/functions/` のみ。

- → 影響: Google OAuth リダイレクトURI＝`{APP_BASE_URL}/api/google-auth-callback`。

### 2. Google OAuth 審査（了解）
- カレンダーは制限付きスコープ。本番公開には Google のセキュリティ審査が必要、と認識。プライバシーポリシー掲載が前提（→ 決定8）。早めに着手。

### 3. ログイン方式
- **Google ソーシャルログイン ＋ メール+パスワード のみ**実装。Apple / LINE は採用しない。
- 認証と外部連携は分離（[features/25](./features/25-auth-architecture.md)）。メール+パスワードでも Google カレンダー連携は後付け可能。
- → 影響: メール+パスワードの登録・ログイン・パスワード再設定・メール確認の基盤が必要。

### 4. 予約ページのURL設計（おすすめ → 決定）

### 5. 通知・メール方針（2026-06-03 更新）
- **メール送信を採用する**。ログイン時に発行者のメール、予約時にゲストのメールを取得するため、**双方にメール通知を送れる**。

- **送信方式は 2026-06-09 会議で決定予定（未確定）**。前提として **2段階認証を避けたい意向**があり、`@gmail.com` から送るにはGoogle経由（アプリパスワード=2FA必須／OAuth=2FA不要だが設定複雑）の制約がある。3案から選択：

  - 詳細・比較は [`mtg/2026-06-09-agenda.md`](./mtg/2026-06-09-agenda.md) §4。決定後にここを確定へ更新し、必要なら実装（②採用時）。SPF/DKIM は ① 採用時に対応。

### 13. メール送信方式（決定）
- **独自ドメイン + Resend を採用**（3案のうち①）。Gmail SMTP / Gmail API 案は不採用（「ちゃんとした会社」イメージ重視）。**レンタルサーバーのメールは不採用**（後述）。

- 〔2026-06-18 更新〕**本番ドメイン = `kimaru-co.jp` を取得済み**（お名前.com・メール用途のみ・サーバー不要）→ [決定24](#24-本番ドメイン確定-kimaru-cojp2026-06-18)。`APP_BASE_URL` 等への反映と送信用サブドメイン/DNS 設定は取得後タスク。

**プラン（更新 2026-06-09）**: **Resend Pro（$20/月 ≒ ¥3,000・50,000通/月）を採用**。猫の会に既に約30名おり月¥3,000は即時許容可能との判断。
- Resend無料枠は **3,000通/月・100通/日**（※従前メモの「500通/月」は誤り）。月間ではなく **「100通/日」上限が先に効く** — 営業ヘビーユーザー（100アポ層）が数人いる日は確認＋リマインドだけで超過し、**リマインダーが送信されない**＝核心機能が静かに壊れる。これを避けるため、無料枠で粘らず Pro にして日次上限を外す。

**送信アーキテクチャ（更新）**: ルートドメインから直送せず、**送信専用サブドメイン**を使い、用途で分離する。
- 取引メール（予約確認・リマインダー・通知）: 例 `notify.kimaru-co.jp` — 絶対到達優先
- 営業メール（サンキュー・登録勧誘・宣伝 → [決定22 会員獲得の自動導線](#22-会員獲得の自動導線将来)）: 例 `news.kimaru-co.jp` — 苦情リスクを取引系から隔離（巻き添え迷惑メール判定を防ぐ）
- 認証は **SPF + DKIM + DMARC**（`p=none` で開始→整合確認後に `quarantine/reject` へ）。**営業系には List-Unsubscribe（ワンクリック解除）必須**（Gmail/Yahoo 要件・2025-11 から非準拠は拒否本格化）。取引系は解除不要。
- 監視: **苦情率 0.3% 未満を維持**＋バウンス済みアドレスは自動サプレッション（Resend Webhook）。

**受信（info@・問い合わせ）**: レンタルサーバーは借りず、**Cloudflare Email Routing（無料転送）で既存Gmailへフォワード**。チームで `info@` 送信もしたくなったら Google Workspace（$6/人）を追加。連絡先メールはドメイン取得後にそのドメインのアドレスへ（それまで暫定 Gmail）。

**レンタルサーバー不採用の理由**: 値段はほぼ同じ（月¥2,600 vs ¥3,000）なのに共有IPで到達率が劣り、SPF/DKIM/DMARCも自前維持。唯一の用途だった「安い受信箱」も Cloudflare 無料転送で代替可。ホスティングは Netlify でサーバー自体が不要。

**将来（AWS SES等）**: AWS は必然の最終形ではない。Resend の中身は SES だが、SES直結で得する差額が運用負荷に見合うのは概ね **月100万通〜**（≒月25〜30万予約＝有料数万人規模）。そこに届いて初めて SES / Postmark / Resend エンタープライズを横並び比較する。送信は `_lib/mail.js` で抽象化済みのため将来の差し替えは局所的で済み、**今決める必要はない**。

### 33. 分析ダッシュボードの中身とタブ構成（2026-08-26）

- **北極星指標は「今月 日程が決まった数」＋「決まったアカウント数」**。キマルが売っているのは日程が決まることで、登録数は無料で溜まるだけ、MRR は結果が遅れて出る（Cat Key の無償Proでも歪む）。予約数と人数を必ず並べるのは、予約数だけだと1人のヘビーユーザーで伸びて見え、人数だけだと1回試して終わった人が混ざるため。
- **タブは5つ**（サマリー / 獲得 / 定着 / 収益 / 機能）。並びは「知る → 登録する → 使い始める → 使い続ける → 払う」という道筋そのもので、落ちている段を上から探せるようにする。設計案では6つ（活性化と継続を分離）だったが、どちらも出口が「誰に声をかけるか」で同じなので **定着** に統合し、中を「立ち上がり」「継続」の2節に分けた。
- **サマリーは期間で絞らない**（全体の累計）。期間タブはこのビューでは隠す（押しても数字が変わらないと壊れて見えるため）。
- **取得できない表は 0 ではなく「取得不可 / 計測待ち」で出す**。0で見せると「機能が使われていない」と読み違えて、間違った打ち手を選ぶ。
- 計測の穴のうち **「有料の壁に当たった記録」と「登録時の流入元」は入れる**（#342）。**内部（運営）アカウントの除外は入れない** — 件数が微々たるもので、除外の仕組みを持つコストのほうが大きいと判断。
- 母数が小さいうちは率が1人で大きく動くため、率には必ず実数を添える（例: 「2 / 5件」と「40%」を並べる）。

### 32. ピンポイント日程調整はプラン別上限つきで全プランへ（決定の配信範囲を更新・2026-08-24）
- ピンポイント日程調整リンク（[30](./features/30-pinpoint-scheduling.md)・#303）の**プレミアム限定配信を解除**し、**全プランで発行できる**ようにする。#303 時点の「当面プレミアム限定」は「まず限定配信して使われ方を見る」ための措置で、恒久的な決定ではないと明記していた。期限（#326）・一覧と無効化（#327）・削除（#336）が揃い機能として閉じたため、プラン差は**数の上限**で付ける。
- 上限（`_lib/plan-limits.js` の `PLAN_LIMITS.*.pinpoint` に集約）:

  | | 無料 | Pro | プレミアム |
  |---|---|---|---|
  | 有効なリンクの同時保有数 | 1 | 3 | 5 |
  | 1リンクあたりの候補数 | 3 | 7 | 30 |
  | 有効期限 | 3日のみ | 3日 / 1週間 | 3日 / 1週間 |
  | 枠の押さえ（仮押さえ予定） | − | ✅ | ✅ |

- **リンク数は「同時保有数」で数える**（累計の発行回数ではない）。累計にすると無料は生涯1本しか作れず、機能を試すこともできない。期限切れ・無効化済みは数えないので、一覧の行を消さなくても次を作れる。
- **候補数の超過は 400 で止める**（多いぶんを黙って切らない）。切ると「7つ選んだのに相手には3つしか出ない」＝設定が黙って消える事故になる（#300 の教訓）。
- **期限は弾かずに丸める**。無料が「1週間」を送ってきたら3日にする（集合判定で弾くと画面から直せない値になる・#300 の教訓）。
- **押さえは Pro 以上**。無料は「押さえない（先着順）」のみ。押さえ＝確実に枠を確保できることを有料の理由にする。判定は Googleカレンダー連携チェックより**先**に行う（無料は連携しても押さえられないので、連携を促す案内を返さない）。
- **降格しても発行済みリンクは切らない**（`plan-freeze.js` の対象にしない）。相手に送ってある約束であり、ピンポイントリンクは最長7日で自然に消えるので凍結の仕組みが要らない。止まるのは新規発行だけ。
- あわせて**リンク一覧の置き場所を変更**（#327 の判断を上書き）: ビュー切り替え（`#pinpoint-list-view`）をやめ、`booking-settings.html` の**予約ページ一覧の下に常設**する。全プランに開放すると、無料は同時1本ゆえ「次を出すために前を無効にしに来る」場所になり、「なぜ作れないか」と「どうすれば作れるか」が別画面に分かれるのを避けるため。リンク0件のときはセクションごと出さない。
- 実装: #338。
