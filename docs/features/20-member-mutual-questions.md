# 20. キマル会員同士の相互質問（双方向）

[← 機能一覧に戻る](./README.md)

- ステータス: ✅ 実装（双方向の回答ループ・会員同士のみ・2026-06）
- 対象プラン: 共通（会員同士のとき有効。無料/有料の差別化機能ではない）
- 仕様: [`../spec.md`](../spec.md) 主要機能 11

> **実装（2026-06）**: 予約者(B)→ホスト(A) の質問は既存の `bookings.guest_message`。新たに、予約者が**キマル会員**（`visitor_email` が `owners` と一致・自己予約を除く）のとき、A への通知メールに「相手からも質問があります。回答をお願いします」＋**回答ページ**（`/answer-question.html`・`hostAnswerToken` で保護）の導線を出す。A が回答すると `bookings.host_answer` に保存し、B へ「回答が届きました」メールを送る。A→B 質問は従来どおり事前アンケートが担う。`questionnaire_*` の双方向化や複数質問の構造化交換は今後の拡張。

## 概要

予約する側だけが情報を出す片方向ではなく、ログイン済みのキマル会員同士なら **予約された側からも相手へ質問を投げられる** ようにする。

## 仕様詳細

- 「○○さんから、この日程で予約が来ました」という通知に対し、受け取った側からも質問事項を返せる。
- プロフィールはお互いに見える状態にする（既に入力済みの情報を、欲しい人に渡せないのは避ける）。
- 双方が会員のときに、より関係構築が進む体験を作る（調整だけで終わるドライな体験にしない）。

## 背景（打ち合わせ）

- 現状のキマルは「予約する側が情報を出す」攻め偏重（＝ポジション・先手が有利）。
- せっかく両者が会員（＝両者課金）なら、相互に質問でき、Zoom 中に「一緒だと良いね」となる体験が望ましい。

## 関連ファイル（想定）

- `public/booking.html` / `book.js` — 予約成立時に「相手への質問」導線を追加
- ログイン状態（`/api/me`）で会員同士かを判定
- DB: `questionnaire_*` の双方向化、または新規の相互質問テーブル
